# RCL v0.5 Simulation Reference Experiment

**Experiment line:** `v0.5`  
**Reference experiment version:** `0.1`

## Purpose

RCL v0.5 begins physical-continuity validation without requiring physical robots to be available on day one.

The first reference experiment is deliberately deterministic and semantic. It validates that the existing RCL migration and repeated Intent Success layers can demonstrate this claim:

> **Robot B may use a different HOW from Robot A while preserving the same declared WHY.**

This is a software reference experiment, not a rigid-body simulator and not physical safety evidence.

## Scenario

The shared behavior is:

```text
behavior
safety.pre_sit_clearance_check

WHY
safety.verify_sitting_area_clear

trigger
activity.before_sit_down

success condition
state.sitting_area_clear
```

### Robot A — source HOW

Robot A does not have a direct sitting-area clearance state.

It has:

```text
perception.directional_attention
x.demo.rear_clearance_classifier
```

Its observed functional strategy is:

```text
source.rear_attention_clearance
```

Conceptually:

```text
turn attention rearward
        ↓
classify rear sitting area
        ↓
confirm clear
        ↓
sit may proceed
```

The rearward check is also represented as a recognizable optional expression.

### Robot B — target HOW

Robot B does not need the rear-attention recipe.

It has:

```text
perception.sitting_area_clearance
```

The capability-path adapter therefore selects:

```text
direct_clearance
```

and declares the target-native strategy:

```text
target.direct_clearance_state
```

Conceptually:

```text
read direct clearance state
        ↓
confirm clear
        ↓
sit may proceed
```

Robot B intentionally lacks `perception.directional_attention`, so the source rearward-look expression is reported as `unsupported` even though the required Intent is preserved.

That is an important expected result:

```text
WHY preserved       → yes
HOW copied          → no
source LOOKS copied → no
migration succeeds  → yes
```

## Evidence shape

Both Robot A and Robot B have deterministic repeated observation series:

```text
3 sessions
× 3 trials per session
= 9 trials per embodiment
```

Every trial observes the same declared trigger and success condition.

The two series use different `strategy_id` values so the experiment cannot pass merely by replaying the same HOW under two robot names.

## PASS conditions

`run_simulation_reference_experiment()` passes only when all of the following are true:

1. Robot A has enough repeated observable evidence for the required Intent to reach `estimated` status.
2. Robot B has enough repeated observable evidence for the same required Intent to reach `estimated` status.
3. RCL migration succeeds.
4. The required Intent migration status is `preserved`.
5. The target selects the expected capability path (`direct_clearance` in this fixture).
6. The observed Robot A and Robot B strategy sets differ.
7. Robot B's observed strategy matches the target strategy declared by the adapter.

The experiment report is validated against `simulation-reference-report.schema.json`.

## Run it

From an installed development checkout:

```bash
python examples/v0.5-sim/run_reference_experiment.py
```

A successful run exits `0` and prints a JSON report containing:

```text
source repeated Intent evidence
target repeated Intent evidence
migration summary
selected capability path
target-native strategy
expression migration status
experiment assertions
```

The same scenario is regression-tested by:

```bash
pytest -q tests/test_v05_simulation_reference.py
```

## What this proves

If the experiment passes, it demonstrates that the reference implementation can compose existing RCL semantics into a repeatable A → B continuity experiment where:

- one declared engineering goal survives;
- the target uses a different semantic capability route;
- repeated goal-success evidence exists on both sides;
- the adapter's target strategy claim agrees with target observations;
- unsupported legacy expression does not masquerade as failed functional Intent migration.

## What this does not prove

It does **not** prove:

- physical dynamics correctness;
- real sensor accuracy;
- actuator safety;
- collision safety;
- timing fidelity on real motors;
- real-world user recognition of the expression;
- physical Robot A → Robot B continuity.

No synthetic observation may be presented as real robot evidence.

## v0.5 validation ladder

This reference experiment is Phase 1 of the v0.5 validation ladder:

```text
Phase 1 — deterministic semantic simulation
        ↓
Phase 2 — hardware-in-the-loop
        ↓
Phase 3 — low-cost physical Robot A / Robot B
        ↓
Phase 4 — richer manipulation / human-interaction validation
```

Each later phase should reuse the same WHY / HOW / LOOKS separation rather than replacing it with a new semantic model.
