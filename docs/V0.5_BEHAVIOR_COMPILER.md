# RCL v0.5 Behavior-Preserving Embodiment Compiler

`Behavior Compiler v0.1` turns migration analysis into an adapter-facing target execution plan.

## Inputs

```text
Compatibility Mapping Report
+ ContinuityScore Report
```

## Output states

- `READY`: direct mapping is policy-compatible, or a substitute has an evidence-backed fidelity assessment.
- `REVIEW_REQUIRED`: substitute is allowed but its behavioral fidelity is still unresolved.
- `BLOCKED`: mapping is unsupported or violates identity policy.

## Why this boundary exists

Compatibility says what the target can represent. ContinuityScore estimates how much identity is preserved. The compiler decides what may proceed to an embodiment adapter without silently converting uncertainty into execution.

## Reference A → B

The current reference plan yields:

```text
following_distance   READY
lateral_offset       READY
acceleration_style   READY
turn_delay           READY
gaze_before_move     REVIEW_REQUIRED
approach_speed       READY
stop_overshoot       READY
```

`gaze_before_move` maps to `body_yaw_attention_cue`, but the substitute has not yet been measured for behavioral fidelity. Therefore the compiler refuses to label the whole plan `READY`.

If later evidence resolves that substitute fidelity, the instruction can become `READY` and carries the assessed fidelity/evidence refs.

## Safety and identity policy

An `UNSUPPORTED` mapping is always `BLOCKED`. Any direct mapping that fails its IdentityConstraint is also `BLOCKED`. Identity-critical blocked constraints are surfaced explicitly in the plan summary.

## Non-goals

v0.1 does not issue motor commands, infer undeclared target capabilities, certify physical safety, or fabricate substitute equivalence. The plan is an intermediate compiler artifact intended for target-specific adapters.

Run the reference with:

```bash
python examples/v0.5-continuity/run_behavior_compiler.py
```
