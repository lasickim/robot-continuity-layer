# RCL v0.5 Generic Sensor Evidence HIL

**Phase:** v0.5 Phase 2 — Hardware-in-the-Loop  
**Reference interface version:** `0.1`

## Purpose

This layer generalizes the first distance-sensor HIL bridge so different sensor modalities can feed the same RCL Intent evaluation path without adding vendor SDKs or raw-sensor assumptions to RCL core.

```text
raw sensor domain
camera / ToF / tactile / audio / IMU / other
        ↓
deployment sensor adapter / perception
        ↓
portable semantic sensor evidence
        ↓
RCL Intent observation
        ↓
existing HIL / capability-path evaluation
```

## Boundary

RCL does not interpret camera pixels, tactile ADC counts, point clouds, or vendor-specific packets directly. Deployment code is responsible for converting raw input into explicit semantic claims.

A `sensor-evidence-series` identifies:

- robot and concrete sensor component;
- sensor modality;
- repeated sessions and trials;
- semantic state claimed by the sensor pipeline;
- `satisfied`, `not_satisfied`, or `not_observable` state;
- optional confidence;
- target-native strategy ID;
- external evidence references.

For example, a camera adapter may produce:

```text
semantic_state = state.sitting_area_clear
state          = satisfied
confidence     = 0.99
```

A tactile adapter can use the same envelope for another declared state, such as a grasp/contact condition, when the corresponding behavior Intent contract exists.

## Why semantic claims rather than raw sensor data

The portable RCL boundary should remain stable when hardware changes. Raw camera frames, ToF drivers, tactile matrices, inference models, and calibration procedures are embodiment/deployment concerns.

The generic layer therefore preserves both:

```text
WHAT WAS OBSERVED
semantic state + state

HOW IT WAS OBSERVED
sensor modality + component + strategy + evidence refs
```

without requiring the RCL core to know one hardware SDK.

## Distance sensor compatibility

The existing `distance-sensor-reading-set` remains supported and unchanged.

`distance_reading_set_to_sensor_evidence_series()` adapts that v0.5 distance boundary into the generic sensor-evidence format. This makes ToF/lidar the first concrete implementation while preserving backwards compatibility with the dedicated distance HIL API.

## Camera and tactile

The generic contract already accepts `camera` and `tactile` modalities. CI uses semantic fixtures only; those fixtures test interface behavior and **do not claim real camera or tactile HIL evidence**.

A real deployment must still satisfy the HIL attestation/evidence gate and retain external evidence showing that the declared sensor pipeline actually participated.

## Sensor fusion

This interface is intentionally single-sensor per series in v0.1. Multi-sensor fusion should be added as a separate composition layer rather than silently merging evidence from multiple components. That keeps provenance and failure attribution explicit.

## What this enables next

The next practical reference can be a camera adapter that records real inference evidence, followed by an explicit fusion layer such as Camera + ToF. A tactile adapter can then use the same generic evidence envelope for contact/grasp Intent states.
