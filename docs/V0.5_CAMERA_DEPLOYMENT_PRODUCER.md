# RCL v0.5 Camera Deployment Producer

This deployment helper closes the gap between a real camera runtime and the existing `camera-perception-series` HIL boundary.

```text
REAL CAMERA
   ↓
deployment frame reader
   ↓
retained frame evidence
   ↓
deployment inferencer
   ↓
semantic predicate + confidence
   ↓
camera-perception-series
   ↓
Camera Semantic HIL
```

## Dependency boundary

RCL core does not require OpenCV, YOLO, TensorRT, VLM, or one Jetson camera stack. Deployments inject two callables:

- a frame reader returning `(frame, frame_ref)`;
- an inferencer returning `semantic_state`, `predicate`, `confidence`, and optional provenance.

`collect_camera_perception_series()` validates and assembles the portable camera evidence series.

An optional `build_opencv_frame_reader()` helper lazily imports OpenCV and supports either a V4L2 device index or a deployment-supported GStreamer pipeline string. Every captured frame is persisted before it can become RCL evidence.

## Jetson pattern

On Jetson, a deployment can use its native OpenCV/GStreamer stack and any perception runtime:

```python
reader, close_camera = build_opencv_frame_reader(
    0,
    evidence_dir="./evidence/frames",
)

try:
    series = collect_camera_perception_series(
        reader,
        my_yolo_or_cv_inferencer,
        series_id="jetson-camera-run-001",
        robot_id="robot-b",
        camera_component_id="csi-camera-01",
        model_id="clearance-model",
        runtime="tensorrt",
    )
finally:
    close_camera()
```

For a CSI camera, the `source` may instead be a GStreamer pipeline accepted by that Jetson OpenCV build.

## Evidence rule

A captured frame must have a non-empty retained `frame_ref`. The producer refuses an inference without:

- semantic state;
- boolean predicate;
- confidence in `[0, 1]`.

This producer does not itself grant HIL evidence grade. The resulting series still must be run through the Camera Semantic HIL deployment path with the existing deployment attestation and external evidence requirements.

## What remains deployment-specific

Camera calibration, focus/exposure, model choice, TensorRT/ONNX/YOLO integration, preprocessing, semantic-state logic, threshold tuning, scene coverage, and physical safety remain deployment responsibilities.
