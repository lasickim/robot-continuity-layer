# RCL v0.5 Distance Sensor HIL

**Phase:** v0.5 Phase 2 — Hardware-in-the-Loop  
**Reference bridge version:** `0.1`

## Purpose

This reference adds one real sensing boundary to the existing HIL experiment without requiring a complete physical robot.

```text
REAL
edge compute
+ distance sensor

SIMULATED
plant
+ actuator / robot body
```

The target Intent evidence is no longer a static target JSON fixture. A deployment sensor driver produces measured distances, which RCL converts into repeated target Intent observations.

## Portable boundary

RCL core does not depend on a specific ToF, lidar, serial, I2C, ROS 2, or vendor SDK.

A deployment driver supplies a `distance-sensor-reading-set` containing:

```text
sensor identity
session / trial identity
measurement timestamp
distance_mm
external evidence refs
```

The deployment may obtain those millimeters from VL53-series ToF, lidar, another range sensor, ROS 2, a serial device, or another trustworthy integration.

## Intent conversion

The reference behavior remains:

```text
WHY
safety.verify_sitting_area_clear

trigger
activity.before_sit_down

success condition
state.sitting_area_clear
```

For this experiment only:

```text
distance_mm >= minimum_clearance_mm
        ↓
success_state = satisfied
```

The threshold is explicit experiment input. **RCL does not define a universal safe clearance distance.** Sensor placement, calibration, field of view, occlusion handling, threshold selection, and physical safety remain deployment responsibilities.

## Evidence boundary

A distance reading set does not automatically become HIL evidence.

The enclosing HIL contract still requires:

- `environment=deployment`;
- real compute and sensor roles;
- simulated plant/actuator boundary;
- external evidence references;
- self-declared runtime attestation.

Therefore CI can test all logic with injected fake readings while remaining `UNCLASSIFIED`.

## Run

First produce a reading set from the deployment sensor driver. Then on the intended edge host:

```bash
python examples/v0.5-hil/run_distance_sensor_hil.py \
  --deployment \
  --reading-set /path/to/distance-readings.json \
  --edge-component-id edge-controller-01 \
  --sensor-component-id tof-01 \
  --minimum-clearance-mm 300 \
  --evidence-ref file:///path/to/raw-sensor-log.json \
  --output /path/to/distance-hil-report.json
```

A successful report requires both:

```text
measured target Intent success
+
HIL execution-boundary eligibility
```

If measured clearance fails, the report remains HIL-grade evidence but the experiment result fails semantically.

## Driver integration

The Python helper `collect_distance_reading_set()` accepts any zero-argument callable that returns millimeters:

```python
reading_set = collect_distance_reading_set(
    lambda: my_sensor.read_mm(),
    reading_set_id="run-001",
    robot_id="robot-b",
    sensor_component_id="tof-01",
)
```

This keeps sensor drivers outside the RCL semantic core.

## What this proves

When executed with genuine deployment measurements, this phase can show that:

- real edge compute participated in the evaluation loop;
- a real distance sensor produced target-side functional evidence;
- Robot B's target-native strategy can be evaluated from measured rather than prewritten target observations;
- the same WHY / capability-path / Intent Success model still applies.

## What this does not prove

It does not prove:

- sensor calibration accuracy;
- complete obstacle detection;
- occlusion robustness;
- actuator correctness;
- rigid-body dynamics;
- collision safety;
- safe sitting behavior;
- complete physical Robot A → Robot B continuity.

Those require stronger HIL and physical validation stages.
