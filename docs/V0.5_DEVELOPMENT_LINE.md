# RCL v0.5 Development Line

**Development version:** `0.5.0-dev` / package metadata `0.5.0.dev0`

RCL v0.5 begins from the frozen v0.4 checkpoint and shifts the primary engineering goal from capability-surface growth to progressively stronger continuity evidence.

## Boundary from v0.4

The v0.4 checkpoint remains historical and unchanged. Its `.rcl` package-format compatibility boundary remains the existing `0.2` five-payload archive format.

v0.5 does not reinterpret synthetic observations as physical evidence. Instead it uses an explicit validation ladder:

```text
Phase 1 — deterministic semantic simulation
        ↓
Phase 2 — hardware-in-the-loop
        ↓
Phase 3 — low-cost physical Robot A / Robot B
        ↓
Phase 4 — richer manipulation / human-interaction validation
```

## Phase 1

The first v0.5 reference experiment is documented in [`V0.5_SIMULATION_REFERENCE.md`](V0.5_SIMULATION_REFERENCE.md).

It deliberately tests one of RCL's central claims:

> Robot B may use a different HOW from Robot A while preserving the same declared WHY.

The reference fixture uses:

```text
Robot A
rearward attention + clearance classifier

Robot B
direct sitting-area clearance state
```

Both are evaluated against the same required Intent across repeated synthetic sessions. The experiment additionally verifies that the target-selected capability path and target-native strategy agree with the target observations.

Robot B intentionally cannot reproduce Robot A's optional rearward-look expression. Functional Intent migration may therefore pass while expression migration reports `unsupported`.

## Evidence labels

For v0.5 development, evidence provenance must remain explicit:

```text
SIMULATION
→ deterministic or simulator-produced evidence

HIL
→ real compute/sensor/controller components with simulated or partial plant

PHYSICAL
→ measurements produced by actual robot hardware in a declared experiment context
```

Synthetic evidence must never be relabeled as physical evidence merely because it passes the same semantic evaluator.

## Current next step

After the deterministic semantic reference experiment is stable, the next target is Phase 2 hardware-in-the-loop. That phase should reuse the same behavior/Intent/capability-path contract and replace only the evidence source or execution boundary that can be made physical.
