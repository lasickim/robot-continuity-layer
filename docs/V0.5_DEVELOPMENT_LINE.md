# RCL v0.5 Development Line

**Development version:** `0.5.0-dev` / package metadata `0.5.0.dev0`

RCL v0.5 begins from the frozen v0.4 checkpoint and shifts the primary engineering goal from capability-surface growth to progressively stronger continuity evidence and behavior-preserving cross-embodiment migration.

## Boundary from v0.4

The v0.4 checkpoint remains historical and unchanged. Its `.rcl` package-format compatibility boundary remains the existing `0.2` five-payload archive format.

v0.5 does not reinterpret synthetic observations as physical evidence. Instead it uses an explicit validation ladder:

```text
Phase 1 — deterministic semantic simulation
        ↓
Phase 2 — hardware-in-the-loop
        ↓
Phase 3 — low-cost physical Robot A / Robot B
        ↓
Phase 4 — richer manipulation / human-interaction validation
```

## Behavior-preserving Continuity IR

The first compiler-oriented continuity layer is documented in [`V0.5_CONTINUITY_PROFILE.md`](V0.5_CONTINUITY_PROFILE.md).

```text
Behavior / Intent
= what the robot is trying to do

BehavioralSignature
= how this robot characteristically does it
```

`ContinuityProfile v0.1` groups context-aware `BehavioralSignature v0.1` records for the source robot. Signatures retain observed trait values, confidence, sample counts, units, and evidence provenance.

Identity importance and preservation policy are intentionally deferred to the next `IdentityConstraint` layer.

The continuity IR is not yet a required `.rcl` payload. The package-format `0.2` five-payload compatibility boundary remains unchanged.

## Phase 1 — semantic reference harness

The first v0.5 reference experiment is documented in [`V0.5_SIMULATION_REFERENCE.md`](V0.5_SIMULATION_REFERENCE.md). It verifies that Robot B may use a different HOW from Robot A while preserving the same declared WHY.

## Phase 2 — HIL and sensor evidence

The base HIL contract is documented in [`V0.5_HIL_REFERENCE.md`](V0.5_HIL_REFERENCE.md).

Phase 2 now includes:

- real edge-compute HIL readiness;
- distance-sensor HIL;
- generic sensor evidence;
- camera semantic HIL;
- deployment-side camera producer with optional OpenCV V4L2/GStreamer capture and injected perception runtime.

CI fixtures validate software contracts only. They must not be relabeled as deployment HIL or physical evidence.

## Evidence labels

```text
SIMULATION
→ deterministic or simulator-produced evidence

HIL
→ real compute/sensor/controller components with simulated or partial plant

PHYSICAL
→ measurements produced by actual robot hardware in a declared experiment context
```
