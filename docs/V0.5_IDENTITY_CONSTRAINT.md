# RCL v0.5 IdentityConstraint

`IdentityConstraint v0.1` separates observed behavior from preservation policy.

```text
BehavioralSignature
= what Robot A characteristically did

IdentityConstraint
= how strongly migration must preserve that trait
```

Each constraint targets one behavioral dimension and declares:

- `importance` from 0 to 1;
- `preservation_mode`: `preference`, `characteristic`, or `identity_critical`;
- whether substitution is allowed;
- whether post-migration adaptation is allowed;
- exact, absolute, or relative tolerance.

Example:

```text
gaze_before_move
importance = 0.95
preservation_mode = identity_critical
substitution_allowed = true
adaptation_allowed = false
tolerance = exact
```

This means a target robot may realize the cue through a different embodiment mechanism, but the migration system must not silently train the cue away after migration.

By contrast, a following distance may be a lower-importance preference with a numeric tolerance and adaptation enabled.

## Validation boundary

Constraints are validated against `ContinuityProfile` before compilation. A constraint cannot silently reference a behavioral dimension that was never observed in the selected source signature.

Context matching remains deterministic. If multiple source signatures exist, callers must supply enough context to resolve the intended signature.

## Not yet implemented

`IdentityConstraint v0.1` does not itself decide `EXACT`, `APPROXIMATE`, `SUBSTITUTE`, or `UNSUPPORTED`. Those classifications belong to the next capability-aware compatibility mapping stage.

It also does not yet calculate `ContinuityScore`. The constraint weights and tolerances introduced here are the policy inputs that the later scoring/compiler stages will consume.

The `.rcl` package-format `0.2` boundary remains unchanged.
