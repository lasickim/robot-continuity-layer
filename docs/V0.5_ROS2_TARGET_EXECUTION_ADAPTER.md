# RCL v0.5 ROS 2 / Jetson Target Execution Adapter

`ROS2TargetExecutionAdapter` is the first reference deployment adapter for `Target Execution v0.1`.

## Flow

```text
Behavior Compiler Plan
→ Target Execution Bundle
→ ROS2TargetExecutionAdapter
→ command envelope
→ command sink
→ ROS 2 topic / service / action / Jetson controller / vendor bridge
```

The adapter intentionally does not hard-code one robot SDK. The deployment owns the final transport through an injected `command_sink`.

## Direct mappings

A READY direct instruction such as:

```text
following_distance = 0.82 m
```

becomes a command envelope conceptually equivalent to:

```json
{
  "command": "set_behavior_dimension",
  "dimension": "following_distance",
  "value": 0.82,
  "capability_id": "locomotion.following_geometry"
}
```

## Substitute mappings

An evidence-resolved substitute such as `body_yaw_attention_cue` becomes:

```json
{
  "command": "execute_substitution_strategy",
  "dimension": "gaze_before_move",
  "strategy": "body_yaw_attention_cue",
  "assessed_fidelity": 0.8
}
```

The adapter rejects substitutes without `assessed_fidelity`. Unmeasured substitutes should have remained `REVIEW_REQUIRED` in the compiler and therefore must not reach target execution.

## Fail-closed behavior

The adapter accepts only instructions with:

```text
execution_status = READY
constraint_satisfied = true
```

This is an additional deployment-side guard; the upstream Target Execution Bundle already denies dispatch for non-READY plans.

## ROS dependency boundary

The semantic adapter itself has no ROS dependency. A deployment can inject any callable sink.

`ROS2JsonPublisherSink` is provided as an optional reference runtime sink using `std_msgs/msg/String`. ROS imports are lazy so normal RCL tests remain usable without ROS installed.

The JSON topic is a reference interoperability transport, not a recommended final real-time control message. Production adapters may use typed ROS messages, services, actions, shared-memory/controller APIs, or vendor SDK calls.

## Jetson deployment

On Jetson, a typical deployment may use:

```text
RCL Python process
→ ROS2TargetExecutionAdapter
→ ROS2 topic/action or local controller bridge
→ robot-specific ROS node / SDK
```

No Jetson-specific dependency is introduced into the RCL core.

## Safety boundary

This adapter does not certify motion safety, collision avoidance, controller limits, or physical suitability. Those checks remain the responsibility of the deployment/controller and target robot integration.
